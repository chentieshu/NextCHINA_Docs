## 3. 覆盖、薄弱内容与日期怎么判断

独立覆盖只认 `knowledgeUnit.kind = independent-explanation` 的明确绑定。长总览、选型清单、价格、榜单和引用入口可帮助理解，但不会填掉独立讲解缺口。一个单元覆盖若干概念时，要逐个检查是否真正解释，不以“提到名字”获得完成状态。

当前知识面板的查找顺序是：自己的资料 → 显式专题引用的直接资料 → 下级资料，同一 articleId 去重。祖先绑定只作为审计背景记录，当前知识面板不会自动把祖先文章下发给叶概念。清单严格分开这几种来源。

“薄弱”按职责处理：

- 概念只有标题、关联或总览：列为待独立解释或待论证共享覆盖
- 已有独立单元：列为草稿存在、待独立复核；更细的子问题仍可能缺内容
- 根/领域/主题/专题：审查目标、范围、次序与有效入口，不要求机械填一篇通用文章
- 分支只有概括句：审查是否准确提出问题、链接规范知识、有正确资源角色；不能把目录提示当正文
- 不用字数、章节数、引用个数或代码通过作为“高质量”的替代指标

### 来源时效

研究元数据最近记录日期仍是 2026-09-27；部分来源和 API 报价记录为 2026-09-26。以 2026-10-05 计是 8–9 天前的记录，**不是本次重新确认过的现价或现行能力**。Arena 的来源快照为 2026-08-06，已相隔 60 天，不应被 9 月的访问日期刷新为最新榜单。

- 价格、产品套餐、接口、模型版本、榜单、政策与标准：作当前选择/主张前重新核验官方来源；保留币种、地区、上下文、计费方式和榜单配置

## 5. 每次补写的质量门槛

对知识单元落实 `master-outline.json` 的完成契约：问题、前置知识、输入输出、机制/公式、例子、代价、失败边界、规范关联、可读资源、证据版本。具体执行时：

1. 先圈定概念和不讲的边界，确认与现有单元的区别，明确要解决的读者问题
2. 找原论文或官方文档；易变事实另作实时核验，标明数据快照和例子是否人为构造
3. 写完整推导/解释与可观察例子，注明适用条件；概念相邻不自动绑定
4. 计算类单元提供标准库可运行例子、误输入、边界输入和不变量；其他类型用可检查的观察/步骤，不硬塞数学
5. 注册同一 articleId，绑定准确概念与已有分支，加入前后阅读链接，避免孤立页面
6. 结构、MD、类型、构建、数值测试和浏览器回归通过；检查真实渲染、公式、宽度、路由往返与控制台
7. 保留 `needs-independent-review`；机器测试不代替专家审查。每个批次要分开报告“新增正文”“明确绑定”“独立审查”
8. 再生成完整清单，检查缺口确实减少而导航/引用没有被冒充独立覆盖，检查源日期没有虚假刷新

## 6. 运行、检查与持续维护

不依赖运行时内容 API、数据库、CMS 或新 npm 依赖。执行：

```sh
# 有意刷新快照：生成完整 JSON、18 个 CSV 和索引（沿用已跟踪索引的审计日）
node scripts/audit-node-content.mjs --write
# 当本次实际复查时间改变时，显式推进审计日
node scripts/audit-node-content.mjs --write --as-of 2026-10-05
# 仅重建忽略的完整 JSON，核对已跟踪 CSV/索引，不静默改写它们
node scripts/audit-node-content.mjs --prepare
# 只检查；JSON、CSV 或索引缺失/过期时非零退出
node scripts/audit-node-content.mjs --check
# 同时检查确定性、成员分区、引用/路由完整性和旧清单拒绝
node scripts/audit-node-content.mjs --self-test
# npm 别名：生成清单 / 确定性与过期检查
npm run audit:content
npm run test:content
npm run validate
npm run build
npm run test:browser
npm run test:production
```

`--check` 是默认只读模式，核对完整 JSON、全部 CSV 和索引。`--write` 才会有意刷新已跟踪文件；`--prepare` 只重建忽略的 JSON 并检查小清单。`npm ci` 的 prepare、predev/prebuild/prelint 均接入后者，因此干净检出无 JSON 时也可安装、构建和运行测试，且过期 CSV 会阻止构建。清单输入哈希包括实际注册 MD、相关 JSON、图构建/资源逻辑与路由契约；尚未注册的草稿不改变已公开内容的快照。清单不用系统时间生成随机变化，`--as-of` 必须显式更新。它不能发现网上来源在本地文件未变时已经更新，也不构成自动监控。

静态路由、候选归一化与默认地图准入检查不等于浏览器逐页验收；浏览器集成测试另跑。重复生成应逐字节一致。新节点必须有明确批次，新增来源形态必须更新生成器，未识别的生成页面应报错而不是猜测事实源。
