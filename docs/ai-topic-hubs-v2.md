# NextCHINA v2：以专题为中心的综合 AI 知识架构

> 阶段：架构与大纲，尚未接入生产界面，尚未拆分或删除现有正文。检查基线：`3fff0fc77c29c3a640d1604bff4b4f6fed103eff`。本方案修正此前“概念节点主要通向总览文章”的组织方式；既有 React Flow/ELK、静态 MD/JSON 和文章 ID 保留。本文是编辑与产品设计，不是声称所有内容已完成或所有事实刚被核验。

## 1. 用户真正需要的结构

LLM 应当是一个可以进入、持续展开的专题，而不是一篇文章的别名。读者进入 LLM 后，应能在同一个专题里找到：是什么、内部怎么算、怎么训练、怎么运行、有哪些模型、能力排名、价格、产品、教程、风险和研究。原来的《LLM 的本质》只是专题中的一个现有阅读资源。

统一原则：**主题内聚合，事实只保存一次；分支负责组织问题，文章负责回答问题，榜单负责呈现有版本的测量结果。**

“属于一个专题”是导航归属，不等于所有内容都是 LLM 的组成部件。例如 RAG 是相关系统专题，不是一个 Transformer 层；使用 LLM 的产品不是一种 LLM 架构。

## 2. 当前代码为什么不能表达这一目标

- `content/garden/blueprint.json` 的结构是 domain → topic → concepts；LLM 位于 language-modeling.concepts，当前没有自己的下级分支。
- `scripts/validate-garden.mjs` 按上述固定层级生成节点；它没有 TopicHub、专题分支和资源集合视图。
- `src/features/garden/data.ts` 的 childrenById 根据单一 parentId 分组；readingEntries 只读取本节点与祖先文章绑定。其他领域中的榜单不会自动进入 LLM。
- `src/features/garden/projection.ts` 只展示当前层孩子或一跳关系，不能将 LLM 的机制、版本、评测与价格组织成目的明确的专题。
- `NodeInspector.tsx` 的核心动作仍然是阅读绑定文章；单纯增大节点、增加连线或加更多文章绑定不能解决专题结构缺失。
- 现有榜单、产品和 API 价格已有独立 JSON 事实源，不能为每个专题另存一份。

因此下一步优先调整内容模型和导航投影，而不是更换 React Flow。

## 3. 信息架构：增加专题层，不推倒原有覆盖地图

```text
全库
  → 知识领域
  → 专题中心（LLM / VLM / Agent / RAG / ...）
  → 分支（机制 / 训练 / 模型 / 评测 / 价格 / 应用 / ...）
  → 子专题或具体问题
  → 原子知识、独立文章、数据集合、模型详情、实验
```

知识领域保留为宏观覆盖地图。榜单、产品和教程保留全局汇总入口，但同一条资料也必须能从所属专题进入。全局入口是跨专题视图，不是与专题割裂的内容仓库。

### 宏观覆盖与专题种子

| 领域 | 应建设的专题，而不是单篇概括 |
| --- | --- |
| AI 全景与入门 | AI 概念、任务与能力、技术历史、人机协作、学习与选型路径 |
| 数学与计算基础 | 线性代数、概率统计、微积分、优化、信息论、数值计算与复杂度 |
| 数据与学习 | 数据生命周期、数据许可、学习范式、泛化、强化学习、迁移与持续学习 |
| 模型与算法 | 经典机器学习、树与集成、搜索与规划、符号与知识推理、概率与因果、神经架构、推荐与时序 |
| 多模态与内容生成 | **LLM、VLM、视觉感知、图像生成、视频、音频语音、音乐、3D 与空间、统一多模态**；Embedding/Reranker 可从这里和检索领域交叉进入 |
| 检索、Agent 与系统 | **Embedding 与检索、RAG、Agent、多智能体、上下文与记忆、工作流、工具与协议、可靠执行** |
| 具身智能与世界模型 | **世界模型、VLA、机器人学习、定位与感知、控制、仿真与现实迁移** |
| 算力与工程部署 | GPU/NPU 与资源、分布式训练、推理服务、压缩与量化、编译与算子、端侧、MLOps、成本与能耗 |
| 评测、榜单与选型 | 评测方法、统计与污染、模型能力、Agent 系统效果、产品适用性、硬件与效率；各专题榜单的全局索引 |
| 产品、工具与生态 | 助手、编程、创作、办公科研、API 与平台、供应商、版本与许可；各专题产品集合的全局索引 |
| 教程与实验 | 使用、开发、训练、部署、数值实验、创作、验收；按目标与难度聚合各专题实践 |
| 行业应用与案例 | 科学与医疗、教育法律金融、工业农业能源、零售物流交通、游戏设计艺术传媒 |
| 安全、伦理与社会 | 幻觉、攻击与防御、隐私权利、运行治理、劳动与社会、公平无障碍、政策与标准 |
| 研究、产业与未来 | 论文与复现、可解释性、前沿问题、公司与团队、产业链、商业模式、证据维护 |

这些是编辑导航，不是一棵互斥的学术分类树。模型的模态、架构、训练方法、能力和运行位置是不同属性；多模态模型可关联多个专题，不复制成多个模型实体。

## 4. LLM 专题完整大纲

LLM 入口显示专题地图、分支、现有资源与缺口。默认不自动打开《LLM 的本质》。首次阅读推荐路径与完整目录同时存在。

### 01 基础与认识

- LLM 是什么，语言建模要解决什么问题。
- 语言模型、大语言模型、基础模型与聊天助手的区别。
- AI / 机器学习 / 深度学习 / 生成式 AI 的关系。
- 预测、生成、检索、推理与行动分别指什么。
- 训练与推理、参数与激活、模型与产品的区别。
- 能做什么、不能保证什么；进入后续各分支的阅读路线。

### 02 表示与数学

- 文本 → Tokenizer → Token ID；BPE/Unigram/字节方案、特殊 Token、中英文长度差别。
- Token Embedding、隐藏状态与上下文表示；与检索 Embedding 模型的区别。
- 向量、张量形状、点积、矩阵乘法、广播与批次。
- 条件概率、自回归分解、最大似然。
- Logits、逐行 Softmax、温度、数值稳定性。
- 负对数似然、交叉熵、困惑度及比较条件。
- 梯度、链式法则、自动微分和优化器。

### 03 架构与内部计算

- Encoder / Decoder / Encoder-Decoder；Transformer、状态空间与混合结构的适用范围。
- Transformer Block：注意力、FFN/MLP、残差、归一化、位置机制、输出头。
- Attention：输入 X 与投影矩阵 → Q/K/V → QK 转置 → 缩放 → Mask → Softmax → 加权 V → 输出投影。
- 多头、MQA/GQA、交叉注意力、稠密/局部/稀疏注意力；区分结构变化与实现优化。
- 位置编码与 RoPE；长上下文相关假设和限制。
- 激活函数、门控前馈层、归一化位置与残差路径。
- Dense / MoE、专家路由、激活参数与总参数。
- 共享概念只保存一份；每个架构明确适用模型或论文，不把示意图说成所有 LLM 的统一结构。

### 04 数据、训练与后训练

- 数据来源、授权、清洗、去重、配比、质量、合成与版本。
- 数据划分、标签移位、掩码、样本打包、测试污染。
- 前向 → Loss → 反向 → 梯度 → 更新；学习率、批次、精度、检查点。
- 训练预算、规模规律、欠拟合/过拟合、训练不稳定与分布变化。
- SFT、偏好数据、奖励模型、RLHF、DPO、可验证奖励及其限制。
- 全量微调、LoRA/其他参数高效方法、持续预训练、蒸馏。
- 上下文学习、RAG、微调如何区分；不是把所有“给模型新信息”都叫训练。

### 05 推理、部署与优化

- 请求组成、聊天模板、上下文预算和输入处理。
- Prefill → Decode；LM Head、生成循环、停止条件。
- Greedy / Top-k / Top-p / Temperature；约束解码和结构化输出。
- KV Cache：读写过程、维度、显存、不同 KV 头数。
- 批处理、调度、前缀缓存、内存管理和服务并发。
- 量化、注意力内核优化、投机解码及质量/延迟取舍。
- 推理时计算、搜索、验证器；区分基础解码与外部系统。
- 本地/云端/端侧部署、兼容性、监控、回滚、停服迁移。

### 06 能力、评测与榜单

- 语言与写作、知识与事实性、数学、代码、指令遵循、多语言、长上下文。
- 幻觉、校准、鲁棒性、安全、拒答与过度拒答。
- 测试任务、采样、工具、推理预算、判分器、置信区间、污染与可复现性。
- 人类文本偏好榜：引用 Arena 的对应快照和口径。
- 综合指标：引用 Artificial Analysis 的指定指数版本和配置，不当作未经解释的普适总分。
- 专项榜：数学、代码、长文、语言、安全等；没有已核验数据时显示缺口，不编榜。
- 性能榜：首 Token 时延、生成速度、吞吐、尾延迟；绑定服务商、硬件与请求条件。
- 相关系统评测：Terminal-Bench 等保留 Agent/模型组合、工具和运行条件；单独分组，不混入裸模型能力排名。

### 07 模型、版本与演化

- 模型家族 → 具体版本 → 已公开变体/配置；供应商为关联实体。
- 输入输出模态、上下文限制、发布日期与停用状态、开放权重/代码/数据的区别。
- 参数和架构只填写已披露资料；未知不按产品宣传推断。
- 同一版本的模型卡、API、评测、报价、产品支持、部署条件与问题记录。
- 多模态模型在 LLM 与 VLM 中共用实体：文本能力评测和视觉能力评测分别呈现。
- 模型版本变化时间线与兼容性，不把指向滚动版本的别名当成不可变版本。

### 08 API、价格与成本

- API 端点、模型 ID、请求/响应、流式、工具调用、速率限制和错误处理。
- 输入/输出/缓存/批量等计价项目、币种、时间、地区与服务商。
- 模型 API 费用与产品订阅分开；优惠、年付折算、常规费用分开。
- 任务成本：输入+输出+缓存+工具+重试+人工复核；不得只用 Token 单价替代。
- 自托管：显存、设备、时长、利用率、能源与运维；所有估算显示假设。
- 价格比较读取同一份报价记录，禁止在专题 Markdown 里维护第二份价格表。

### 09 应用、产品与系统

- 通用聊天、写作、代码、研究搜索、文档问答、数据分析等任务。
- 按任务筛选产品；区分产品、API 服务、模型与开发框架。
- RAG / Agent / 工作流为相关专题：这里说明 LLM 扮演的角色，再进入各专题。
- 产品 → 支持的模型版本 → 服务商 → 套餐 → 教程 → 实测；每条关系注明来源与有效时间。
- 行业应用保留业务基线、人工参与、收益和失败条件，不把工具列表当行业证据。

### 10 教程、实验与案例

- 第一次使用、提示与核验、第一次 API 请求、本地运行。
- Token 编码实验、Softmax 手算、完整注意力数值步骤。
- 一个 Loss 和梯度更新、小模型训练、微调对比。
- RAG/Agent 集成实验、结构化输出与失败恢复。
- 同一任务比较模型、测延迟与成本、写可复现评测报告。
- 每篇教程包含前提、版本、成本、操作、预期输出、排错、限制；大纲不是完成教程。

### 11 边界、安全与治理

- 事实错误、上下文遗漏、不确定性、偏差、多语言边界。
- 提示注入、数据泄露、工具越权、防御与人的确认。
- 数据/权重/输出的许可、隐私、来源追踪、审计与事件响应。
- 法域、时间和业务场景分开，不提供脱离适用范围的“合法/合规”总标签。
- 模型安全、系统安全、产品政策与部署环境分别讨论。

### 12 论文、证据与研究进展

- 基础论文 → 机制解读 → 数学假设 → 复现与消融 → 局限。
- 研究主张、厂商声明、本站实验、编辑推断分别记录。
- 架构、数据、训练、推理、对齐、解释性、效率的演进路线。
- 未解决问题、争议、负结果和错误案例，不把方向性判断写成已证实结论。
- 更新记录与证据日期；修改分类不刷新原事实的核验日期。

## 5. 从分支到微观内容的完成标准

Attention 不是一个只跳回总览的空文件夹。它应能继续进入 QKV、矩阵乘法、缩放、Mask、Softmax、加权输出；每个知识单元回答：解决什么、输入与输出、变量和形状、最小数值例子、假设、错误案例、相关实现、证据与下一步。

例如“KV Cache 显存”页面同时关联一次具体形状的计算实验、KV 头结构、部署硬件、相关模型的已披露规格和实际服务约束。公式以显式假设计算，不能从模型名字猜测未公开参数。

同一概念可在不同专题出现多个导航位置，但都引用一个 concept ID。专题内解释负责上下文与差异；通用公式正文不复制三份。

## 6. 其他专题怎样展开

| 专题 | 专属原理分支 | 应聚合的评测/资源 | 特别边界 |
| --- | --- | --- | --- |
| VLM | 图像表示、Patch/ViT、对齐、连接器、跨模态融合、OCR/Grounding、视觉推理 | 视觉任务评测、支持视觉的模型版本、图像计价、视觉产品、文档图表问答教程 | 输入图像并输出文本与“生成图片”不是同一任务；文本榜不能代替视觉榜 |
| 图像生成 | 扩散、Flow、潜变量、DiT、条件控制、编辑 | 图像质量与提示遵循、模型版本、按图/API费用、创作产品、工作流、权利 | Diffusion/DiT 是相关机制，不是全部图像 AI |
| 视频 | 时空表示、时序一致性、运动与控制、声音同步 | 视频评测、版本、时长/分辨率计价、视频产品、镜头教程、失败案例 | 视频生成、视频理解、动作条件世界预测分开 |
| 音频/音乐 | 波形频谱、识别、合成、Codec、实时语音、音乐结构 | ASR/TTS/对话/音乐专项评价、模型、时长费用、产品与制作教程 | 语音与音乐可互相关联但不能只有一个不分任务的“音频总榜” |
| 3D/空间 | 几何表示、重建、NeRF/3DGS、网格、材质、动作 | 几何/外观/可用性评价、生成重建工具、格式与资产管线教程 | 参数化/CAD、可渲染外观、拓扑可编辑性分开 |
| Embedding/检索 | 表示、对比目标、相似度、稀疏/稠密检索、索引、重排 | 语种与任务评测、模型、向量长度/费用、搜索产品、检索实验 | Token Embedding 不等同检索模型；召回与重排分开 |
| RAG | 文档处理、分块、召回、重排、上下文、引用、回答验证 | 检索/生成/端到端指标、组件模型、系统费用、框架与实验 | 不伪装成一种基础模型，不编不存在的“RAG 参数量” |
| Agent | 目标状态、计划、工具、记忆、执行反馈、权限、恢复、多智能体 | 系统榜、模型与工具组合、任务总成本、成品与框架、任务复现 | 任务成绩不能全归因于底层模型 |
| 世界模型/VLA/机器人 | 状态动作、动力学、感知控制、仿真、策略学习 | 任务与环境版本、轨迹/成功率、模型/数据/硬件、仿真实验 | 安全边界和现实迁移不能被视觉演示代替 |
| 数学/算法基础 | 定义、假设、推导、算法、数值、反例、实现 | 相关模型、复杂度、论文与练习 | 不机械生成“矩阵乘法订阅价格榜” |
| 行业/治理 | 任务基线、数据与流程、组织与人的参与、评价、风险 | 案例、产品、证据、适用地区时间 | 医疗/法律等不从软件能力推导专业结论 |

全部专题共享“解释—机制—证据—实践—关联”的原则，但分支按主题类型定制。不适用项省略，未知项保留未知，未完善项显示大纲，三种状态不同。

| catalog-text / catalog-code | LLM / 应用与产品；助手/编程专题 | 是任务产品目录，不等于已证明所有产品使用某个模型版本 |
| agent-products | Agent / 产品与框架；LLM / 相关系统 | 保留产品与框架类型，非严格热度排名 |
| 其他模态原理/产品目录 | 对应 VLM、图像、视频、音频、音乐、3D、检索专题 | 同一正文/数据多入口，不复制 |
| apple-style-premium-product-video | 教程 / 视频制作；视频专题 / 创作方法 | 继续保留教程归属与原文章 ID；不因 LLM 专题改造移入 LLM |
| sources-and-gaps | 研究证据 / 维护规则；各专题来源入口 | 分类更新不是事实复核 |

### 榜单关联的正确粒度

模型版本与模型家族分开；同一模型的不同推理模式可能是不同 EvaluationConfiguration，不默认创建一个新的基础模型版本。一次评测包含：evaluationRunId、subjectType、modelVersionRefs（可多模型）、agentVersionRef（可空）、benchmarkVersion、datasetSplit、harness/config、推理预算、工具、硬件/服务商、指标、时间和证据。

用稳定引用连接 modelVersion、evaluationRun、leaderboardSnapshot、source。不能用名称包含“LLM”或供应商相同就关联；名称别名与版本映射单独审核。部分旧数据只有 name/provider，应保留 unresolved 状态，不虚构版本 ID。

专题榜单是从规范快照中筛出的视图。保留原名次；筛选序号只能叫“当前列表序号”，不能改写源榜排名。不同版本/预算/数据集的分数不直接相加；没有可比组就分组展示。缺失分数是 null，不是 0。

### 费用归属

PriceOffer 绑定具体服务商、模型版本或产品套餐、币种、单位、地区、有效时间和来源。一个模型可有多家服务商报价；产品订阅不覆盖 API 账单。客户端只有取得已确认的模型版本与能力标签时才自动筛选，第一阶段仅提供清楚标注的现有资料入口。

## 8. 数据模型与静态工程

```text
TopicHub（hub:llm）
  about → CanonicalConcept（concept:llm，身份不变）
  branches → NavigationOccurrence（可以递归）
    reference → 共享概念 / 独立文章 / 实验 / ResourceView
ResourceView
  resolves → ModelVersion / EvaluationRun / PriceOffer / Product / Source
```

TopicHub 是编辑专题；Concept 是知识实体；Occurrence 是它在某专题的导航位置。三者 ID 不混用。`concept:softmax` 可以被 LLM、Attention、采样专题共同引用；`hub:llm` 的“应用”分支关联 `hub:rag`，不改变 RAG 的规范身份。

建议后续实现路径：

```text
content/topics/index.json                # 已接入的专题清单（后续）
content/topics/llm/navigation.json        # LLM 递归导航（后续）
content/topics/llm/resources.json         # 数据源筛选与跨专题引用（后续）
content/knowledge/**/*.md                # 按审核结果逐步拆出的独立知识文章（后续）
content/entities/**/*.json               # 版本/供应商/数据集等规范记录（后续）
content/data/benchmarks.json             # 先继续复用
content/data/model-api-prices.json       # 先继续复用
content/data/products/*.json             # 先继续复用
content/garden/plans/topic-hubs-v2.json   # 本轮：尚未接入的架构清单
```

构建顺序：读取规范记录 → 校验引用与证据状态 → 编译专题树/双向索引/资源视图 → 静态 JSON 与搜索索引 → 按需加载。无需数据库、后台或运行时抓取 API。价格榜单不放进内容节点正文，阅读与画布共用 topic resolver。

未来渲染器需要接收统一的 ViewNode：hub、branch、concept-reference、resource-collection、entity-reference、article-reference、experiment。React Flow 仍负责渲染与交互，ELK 负责局部排版，不能用布局来自动决定科学关系。

## 9. 页面、侧栏与图谱是一套导航

LLM 专题首页展示十二个折叠分支；读者可按“理解原理/选择模型/动手实践”跳到分支，但不建立重复课程事实源。侧栏展示同一 navigation，画布将同一节点与关系可视化。进入“能力榜单”时，中心区域显示可用的比较视图，不把几十行分数塞进节点卡片。

示例目标地址：`?view=topic&topic=llm&section=rankings`。这是拟议路由，不是本轮已支持的地址。旧 `view=garden&node=concept:llm` 在接入后进入专题或显示专题入口；旧文章 URL 保留阅读能力，提供“进入 LLM 专题”。

模型详情在当前专题上下文内打开，显示版本、能力、来源、可比评测、报价、产品和教程。返回专题保留选中的分支、比较筛选和图谱视口。

手机用分支列表或局部图，不把十二个分支和所有后代一次缩到一个屏幕。低缩放合并为分支卡片，按需展开；阅读和榜单是有尺寸约束的主面板。沿用无阴影、明暗主题和局部横向滚动规则，不增加本文大纲，不恢复原生 select 外观。

## 10. 迁移步骤与验收

1. 本轮：提交全局架构、LLM 详细大纲、其他专题模板、现有 23 页的目标映射和只读计划校验。不修改运行时图谱、依赖或数据事实。

3. 内容阶段：先拆 Token、概率与采样、Attention、训练与后训练、推理与 KV Cache 等独立模块。每个模块补定义/数学假设/例子/证据，再更新原总览为导航介绍；未拆分内容继续可读。
4. 数据阶段：规范化已证实的模型版本、评测运行和报价关系；尚未精确映射的记录保持 unresolved，再启用动态过滤视图。
