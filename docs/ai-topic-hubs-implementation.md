# 专题中心：LLM 多级大纲与资源接入

本阶段将 ai-topic-hubs-v2.md 的组织方案接入现有 React Flow 花园。不是把《LLM 的本质》复制成多篇文章：专题、分支、共享概念和文章保持不同身份。

## 入口

首页的“LLM 专题”，以及花园顶部的同名按钮，进入 `?view=garden&scope=hub%3Allm`。默认是专题目录；读者可以切换图谱。旧 `concept:llm` 节点保留，详情和展开动作提供专题入口，旧文章链接不变。

LLM 十二主分支：基础与认识、表示与数学、架构与内部计算、数据/训练/后训练、推理部署优化、能力评测榜单、模型版本演化、API价格成本、应用产品系统、教程实验案例、安全治理、论文证据进展。

Attention 可继续展开为 QKV、分数、缩放、掩码、Softmax、加权 V、多头。KV Cache 可继续展开缓存读写、显存形状、前缀服务。分支叶子尚无独立正文时，明确显示缺口，不自动跳回同一篇总览。

## 规范数据与派生数据

- `content/garden/plans/topic-hubs-v2.json`：上一阶段审定的大纲与文章放置计划，保留原计划阶段标注。
- `content/garden/hub-integration.json`：本阶段启用范围、分支说明和具体资源放置，是实际接入配置。后续变更大纲必须同步通过此集成验证。
- `scripts/build-topic-hubs.mjs`：将大纲投影为 hub/branch 导航对象，与旧概念图组合。共享概念 parentId/ID 不变。
- `scripts/prepare-garden.mjs`：开发和构建前输出 `src/generated/garden.json`，包含专题节点、资源元数据及引用；派生文件不进入 Git。
- 原 `.md`、榜单/价格/产品 JSON 继续是事实源。专题不维护第二份手写榜单或价格表，不修改核验日期。

hub 的 articleBindings 为空，不是一篇文章的别名。分支资源只来自显式配置，`readingEntries` 不将祖先总览继承为每一个子问题的正文。通用概念保留旧有明确标注的总览入口。

## 资源组织

`LLM / 能力、评测与榜单` 分别进入 Arena、Artificial Analysis 和相关 Agent 系统任务评测。Terminal-Bench 在入口和正文提示中都标注不是裸模型能力榜。

`LLM / API、价格与成本 / API 报价` 在专题中渲染现有规范文档，保留各条目单位、来源与日期。产品订阅仍与 API 分开。

`LLM / 应用、产品与系统` 连接助手、编程、Agent、平台目录；RAG 和 Agent 为相关系统专题，不视为 Transformer 层。产品目录并不证明其中每个产品已核验绑定某个模型。

`LLM / 模型、版本与演化` 提供来源记录索引。按原模型评测记录显示名称、供应商记录、快照和证据入口，不模糊合并名称，不推断精确版本、参数、模态或报价映射。未知来源入口不能自动冒充 AA。Agent 系统记录不混入此模型索引。

Apple 视频教程仍在原“教程 / 视频制作”。专题导航同时从“视频 / 教程”和“视频制作实践 / 工作流”引用同一篇正文，不放进 LLM 教程。

其他已启用专题只接入有现成资料的分组，不批量生成 profile 中的空文件夹。RAG 等暂时没有独立资料时，显示专题说明与共享概念，完整专属大纲仍待后续建设。

## 界面与响应式

同一套 hub/branch ID 驱动树状目录、分支卡片、React Flow 子图、搜索、面包屑和 URL。桌面展开专题时左侧切为该专题的递归分支目录；窄屏用卡片和面包屑，不把三栏挤进手机。

专题卡片以内容容器宽度决定列数，长标题换行。内容区独立滚动；数据表继续使用原 Markdown 局部横滑容器。无阴影、明暗主题、焦点提示和窄屏详情的 inert/焦点约束继续沿用。

资源叶子可在专题内阅读完整现有数据页，也可进入文档阅读器。读取文章携带原花园 URL，返回、刷新、浏览器历史恢复同一分支。未创建新的任意 return URL 或跳转执行通道。

## 验证与维护

`npm run test:hubs` 验证递归导航、规范概念不变、23 个页面的资源引用、数据不被修改、7 类错误输入与缺失来源。`npm run build` 已包含此检查。`garden-hubs.spec.ts` 在开发和生产产物测试中都执行，覆盖主题、移动宽度、深层分支、共享概念、数据页、文章返回和图谱切换。

安装依然 `npm ci`，没有增加依赖，也不改变 Cloudflare 凭据。实现首先在验证分支测试，再合入主分支；以对应 GitHub Actions 结果判断部署状态，不用旧成功记录替代新提交。
