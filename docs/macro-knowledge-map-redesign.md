# 宏观知识地图：结构、关系与阅读闭环

## 目标

全站保留一张 AI 知识地图。地图回答三个问题：知识位于哪里、它与其他知识有什么关系、可以读什么。它不是可编辑白板，也不是把所有节点一次性铺开的关系可视化演示。

保留现有无 titlebar、无多文档标签的学习工作区。文档仍由侧栏选择，在同一个阅读器打开。没有为每篇文章建立第二张图。

## 源码审阅发现

本次审阅基线为 `2bc0c17e1c680a5627aa48a6c41ae5e93b50862e`。审阅覆盖图谱入口、图形渲染、投影、知识生成、专题叠加、目录模型、路由、阅读器、样式与现有浏览器测试。

| 原实现 | 问题 | 新实现 |
| --- | --- | --- |
| WorkspaceGraph 的 detail / expandedId 和 GardenCanvas 的 projection key | 搜索和展开会改换密度、重建画布；同一节点的探索位置不稳定 | 首页地图拓扑固定，选择仅改变详情和所属区域高亮 |
| GardenCanvas 在 macro 模式提前退出选中定位 | 宏观节点被选中但可能不在可读视野中 | 按所属区域定位，不缩小文字、不重新布局 |
| 节点简报只显示关系数量 | 用户看不到关系另一端与关系理由，探索无法继续 | 每条关系展示两端、关系种类与原始说明，两端均可选中 |
| globalKnowledgeProjection 通过 reason 正则排除部分专题引用 | 知识复用关系与图上显示脱节 | 按显式 conceptRefs / hubRefs 识别引用，并保留全部原始边 |
| 学习路径相邻步骤被合成为 recommended_before | 建议阅读顺序被提升成知识关系断言 | 路径单独展示，不生成知识关系边 |
| 宏观投影只保留每组关系的第一条记录 | 无法从汇总连线追溯全部原始关系 | 连线保留 relations 数组，完整展示原始边 |
| 选中状态只在局部 React state 中 | 刷新、前进后退和阅读返回不能定位原节点 | URL 保留 canonical node ID；文档链接保留安全 return 状态 |
| 概念节点统一提供“打开对应目录” | Explorer 不一定具有该目录，会进入空入口 | 只为真实存在的目录提供目录操作，概念直接通过详情探索 |
| 直接资料、引用资料、下级资料混为一组 | 容易把“有资料”误读为“本知识已写完” | 资料明确标注直接绑定、通过专题引用、下级资料；独立讲解单独计数 |

旧投影与旧画布模块仍保留在代码库供后续清理，本次首页不再依赖它们。不能据此声称历史代码已全部删除。

## 宏观地图

区域直接来自 blueprint 的六个 groups，不维护第二份分类：

```text
建立全景              数学、数据与学习          模型、算法与模态
    ↕                       ↕                        ↕
系统、Agent 与工程     评测、产品与实践          应用、治理与前沿
```

上图仅说明六个区域的排布，不声明箭头所代表的科学或先修关系。实际界面只绘制由原始关系汇总得到的跨区连线。

区域内展示领域和已有专题入口。更细的专题、分支和概念通过下级知识、关系两端以及搜索到达。所有入口都使用同一个规范节点 ID，不复制概念。

桌面采用可读字号的分区地图；较窄容器自动变成两列，手机变成单列。手机不要求拖拽、双指缩放或寻找画布角落。窄屏隐藏容易拥挤的装饰连线，但每个区域仍有“查看关联”入口，原始关系不会消失。

区域位置不是概念距离、因果强度或严格学习顺序。宏观布局服务于阅读，而不是额外的知识断言。

## 同一份数据的多个入口

```text
blueprint + 专题计划 + 文章/知识单元注册
                    ↓ 校验与生成
               generated/garden.json
                    ↓
             buildKnowledgeIndex
        ┌───────────┼───────────┐
    宏观区域地图  双向关系索引   资料来源索引
        └───────────┼───────────┘
              canonical node ID
                    ↓
          搜索 / 下级知识 / 关系两端
                    ↓
                文档阅读器
                    ↓ 安全 return URL
               原知识节点
```

### 关系语义

- **目录归属**：由 parentId 表达，不能冒充知识包含、科学因果或建议先学。
- **知识关联**：保留原始 related 边及编辑说明，界面采用双向展示。
- **建议先学**：仅使用已存在的 recommended_before 边，方向为先了解的知识到后续知识。
- **专题引用**：由源节点的 conceptRefs / hubRefs 显式识别；与科学关联分别展示。
- **学习路径**：独立有序引用列表，标为规划路径，不生成推荐先修边。

这些是读取现有数据的语义规则，不意味着现有内容已经覆盖全部 AI 知识，也不代表编辑关系已获得专家核验。

### 汇总的完整性

每条非目录关系必须归入且只归入以下一处：同一区域内部关系，或一个跨区关系汇总包。汇总不改写原始 edge ID、source、target、type、reason 和 assertionStatus。

两端节点均出现在双向邻接索引中。用户从任一端都可以继续探索。区域连线没有方向箭头，避免将具体知识的先后顺序推广为整个领域的先后顺序。

### 资料的完整性

同一文章只维护一份正文，节点通过 article ID 引用它。资料按以下优先级去重：直接绑定、通过专题引用、下级资料。去重不把后两类提升为直接绑定。

独立讲解只统计本节点直接绑定、coverage 为 explanation 或 independent-explanation 的资料。“有资料”和“本知识完成独立讲解”不是同一状态。

## 交互约定

| 操作 | 结果 |
| --- | --- |
| 点击领域、专题或搜索结果 | 选中规范节点，高亮所属区域，打开详情；不重排地图 |
| 点击下级、面包屑或关系另一端 | 更新同一张地图的选中节点，并写入浏览器历史 |
| 点击跨区连线 / 区域查看关联 | 查看该范围内全部原始关系，可筛选、逐批展开 |
| 点击“知识关联” | 查看完整关系索引与独立学习路径 |
| 点击阅读资料 | 打开现有单文档阅读器，携带原节点 return 状态 |
| 继续阅读另一篇资料 | 保留最初的地图来源 |
| 点击“返回知识地图” | 返回原规范节点，而不是丢失上下文的首页 |
| 浏览器刷新、后退、前进 | 从 URL 恢复规范节点或文档 |
| 点击关闭 / 回到全貌 | 清除选择并回到全局地图 |

桌面详情区域固定占位，选择前后不会挤压地图。窄屏详情采用对话框，提供焦点约束、Escape 关闭和导航恢复。全局地图不再同时打开第二个“关联资料”侧栏。

## 实现边界

- `knowledgeIndex.ts`：纯数据索引，可脱离 DOM 测试。
- `AtlasMap.tsx`：稳定分区与跨区关系线，使用原生布局和 ResizeObserver。
- `WorkspaceGraph.tsx`：搜索、节点详情、关系索引和阅读入口。
- `Workspace.tsx`：URL 恢复、阅读返回、统一工作区入口。
- `atlas.css`：只对 atlas 命名空间生效的响应式样式。

本次没有更改模型排名、分数、价格或文章证据状态，也没有声称重新核验这些内容。保留原有内容校验和部署流程。

## 验收

数据测试检查全部节点可归区/可搜索、全部语义边完整分配且无重复、两端可访问、显式先修边不增加、引用关系来源明确、资料去重与覆盖状态正确。

浏览器回归覆盖 320 / 390 / 768 / 1024 / 1280 / 1440 / 1920 像素和明暗主题；无页面横向溢出；地图文字不通过整体缩放变成不可读；选择前后地图 DOM 和区域坐标稳定；刷新及阅读返回能恢复节点；移动详情可用键盘关闭；禁用布局 worker 不影响新地图。

测试脚本已纳入现有 workspace-home.spec.ts，继续由仓库原有 development 与 production 两组 Playwright 工作流执行。测试是否通过必须以实际 CI 结果为准；本设计文档不作为通过证明。
