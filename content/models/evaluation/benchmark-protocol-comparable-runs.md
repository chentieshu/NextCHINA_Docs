> **本页解决的问题**：看到 A 得 6/8、B 得 5/6，先别排先后。分母里是谁，超时怎么算，允许几次尝试，比较的是模型还是带工具的系统，都会改变这两个数回答的问题。

**评测协议**是把受测对象、任务实例和允许的资源，变成输出、判定与报告的事先约定及执行流程。它既要说明“计划怎样测”，也要留下“实际怎样测”的证据。本页用八项虚构包裹分流任务，练习从清单、逐项日志和后来的审计证据写出有边界的比较结论。

## 1. 先写问题，再决定哪些条件相同

“哪个更好”还不是一个完整问题。先确定受测对象：

- **基础模型**：希望比较模型本身在指定接口下的表现，需要控制与该问题有关的适配、资源和评价条件；名称相似不代表模型版本相同
- **适配后的预测流程**：模型加预处理、提示、解码或分类头，评价的是这套明确版本的组合
- **带工具的系统**：模型加检索、调用工具、重试和结果选择，评价边界包含这些组件
- **部署配置**：若问题包含时限、硬件或费用，就必须把相应运行环境和计时、计费边界写进协议

HELM 的术语把任务实例及参考答案、适配过程、指标分开描述；其附录另列提示格式、解码与停止条件。它提醒我们：同一题库不会自动确定“怎样得到答案”。这是语言模型中的具体方法例子，并非所有任务都应采用同一种提示策略。[HELM v2，§2.1–2.3、附录 J](https://arxiv.org/pdf/2211.09110v2)

可比性总是相对于一个问题。研究“同资源下哪套配置完成更多任务”，就应匹配相关资源；研究“各自在允许预算内的完整系统表现”，则可以事先允许不同工具或硬件，并报告差异。不是所有字段都必须机械地相等，也不能在看完分数后把意外差异重新包装成原计划。

早期 MLPerf Inference 论文把质量要求和使用场景纳入系统性能评价，也讨论实际提交的审计。这支持先声明场景与质量约束、再核查运行证据的思路；本文不把该论文 2020 年的具体目标或规则说成 2026 年现行规定。[MLPerf Inference v2，§III.B–C、§VII.E](https://arxiv.org/pdf/1911.02549v2)

## 2. 一份可追踪的协议需要什么

把“约定”和“发生过的事”分开保留。以下是本页的整理方式，不是照搬某篇论文的通用合规表。

| 需要界定的事 | 约定与执行证据 |
| --- | --- |
| 目的与对象 | 要回答的问题；基础模型、流程或系统；允许改变什么 |
| 任务与参考 | 输入输出定义；题目集合、切片和标签版本；排除规则 |
| 运行配置 | 模型、预处理、提示、工具及配置版本；适用的环境、随机设置 |
| 资源与停止 | 每题尝试数、时限、工具调用预算；错误后是否重试；如何选答案 |
| 评价与报告 | 判分器版本；超时、弃答、无输出的处理；分母与聚合方式 |
| 开发与选择 | 搜过哪些配置、何时看过哪些答案；停止开发和选定结果的规则 |
| 实际记录 | 每题实际输入、输出、状态和必要时序；哪些偏离尚未解释 |

“超时”说明到声明的截止时刻仍未得到响应或完成；及时返回的错路线或无效格式仍是已完成的失败，不能记成超时。“弃答”是系统明确选择不作决定；“答错”可以是完成后给错路线，也可以是格式不被判分器接受。三者不能在日志里混为一谈，是否都计失败则由所问问题和预先声明的政策决定。一个只评价已完成答案的辅助指标可以有用，但不能顶替承诺的全任务指标。

记录随机种子、环境和配置标识有助追踪；哈希可以帮助核对某个文件是否一致，却不能证明系统真的用了它，也不保证随机服务或不同硬件得到完全相同输出。对于时延比较，负载、并发、预热、计时起止与环境尤其重要；本页只用时间判断虚构截止是否触发，不据此评比真实速度。

Pineau 的 v2.0 检查表要求交代排除与预处理、配置选择、运行次数、指标和计算条件。这里把这些要求落到“该补什么记录”的问题上，不把填表当作正确性的证明。[机器学习可复现性检查表 v2.0，第 1 页](https://www.cs.mcgill.ca/~jpineau/ReproducibilityChecklist.pdf)

### P1：同一有限任务集上的一次尝试

**已给事实：** 使用共用清单和全部八项基线记录。A 有六项正确、两项错误；B 有五项正确、一项格式错误、两项超时。

**先问：** 按声明规则该报什么分数？能否由此宣布 A 的模型能力普遍更强？

**有界判断：** A 的全任务成功比例为 $6/8=75\%$，B 为 $5/8=62.5\%$。在这八项、这两个冻结系统和这套一次尝试协议下，A 多成功一项，比例相差 $1/8$，即 12.5 个百分点。

**理由：** 计分单位是预定任务，不是只保留下来的响应。A、B 的输出都按 S1 和同一 L1 计分，失败项仍占分母。这个结论完整说出了对象、集合与运行条件。

**缺失证据：** 没有目标总体的抽样依据，不能推断总体差异或显著性；没有相关随机过程的重复设计，不能保证下次仍如此；两套系统并非只改变一个组件，不能作基础模型改进的因果归因。不是说它们必然没有差异，而是这些更强结论尚未建立。

**修复或下一步：** 若需要总体判断，先定义目标工作量和取得证据的方式；若需要隔离某个组件，应设计对应的受控比较；若关心重复运行的波动，要冻结重复与报告规则。不要仅给这个小表加一个区间就跳过这些问题。

### P2：删除超时后，分数究竟换成了什么

**已给事实：** 新报告仍写 A 为 6/8，却从 B 的报告删除 p7、p8 两条超时，写 B 为 5/6，并把两者都叫“准确率”。运行本身没有改变。

**先问：** 5/6 算错了吗？它能取代基线的 5/8 吗？

**有界判断：** $5/6\approx83.3\%$ 算的是 B **已完成尝试中的正确比例**。它算术上有意义，却不是预先声明的全任务成功比例。主要结果仍应为 A 6/8、B 5/8；可以另报 B 完成了 6/8，并在这六项中正确 5/6。

**理由：** B 的两项超时没有变成正确答案，也没有因为没有输出就不再是任务。用 A 的全任务比例与 B 的完成条件比例排序，改变了分母所代表的集合。若一开始确实要研究完成后的答案质量，也必须明确条件并同时交代未完成情况，不能据此冒称完成了更多任务。

**缺失证据：** 这份记录不知道 B 超时项在更长时限下会答什么；不能补成“可能正确”，也不能从完成子集替代它们。

**修复或下一步：** 恢复两条超时记录与八项主分母，保留原错误报告及更正说明。区分主结果、完成率和完成后的质量，不必把后两者全部删除。

### P3：固定两次尝试与知道答案的离线判分

**已给事实：** 另有 `run-B2`，仍用 B1 配置 C-B1 与 D1、L1、S1，无工具；允许预算从每题一次改为**每题固定两次**。这是“最多两次”的一种明确实现：每题都用满两次，而非答对就停。第一次与第二次的种子设置分别为 11、12；第一轮的数值碰巧同基线 B，但它们是此分支的新记录，没有复用 `run-B1`。

完整资源政策是：八题各启动两次，共 **16 次生成**；每次上限 3000 ms，串行生成时间预算上限为 $16\times3000=48000$ ms，不含编排与离线评分开销。第一答正确、错误或超时，都照样启动第二次。生成器看不到 L1，停止决策不能查正确答案；离线判分器则读取 L1，按“两次中任一次正确”给该题记成功。没有另行提供部署选择器。

**先问：** 任一次正确的题目比例是多少？能否把它当成 B 部署时会返回正确答案的比例，或直接当成相同预算下的模型进步？

**有界判断：** p1–p7 各至少有一次正确，只有 p8 没有，所以这一**两次尝试、参考答案辅助的离线诊断**为 7/8。它不是一次尝试的 7/8，也没有证明一个可部署选择器达到 7/8。

**理由：** p1、p3、p5 两次输出互相冲突。离线判分可以看 L1 来判断其中有正确答案，部署端通常不能预先知道 L1。算出“候选中存在正确答案”不等于实现“选中正确答案”。这里既没有按真值停止生成，也没有声称真值选择能上线。第二次未必独立于第一次，因此只逐项核对记录，不把失败概率相乘推算成功率。

**缺失证据：** 缺少不读参考答案的最终答案选择政策，以及按该政策产生的最终响应记录。固定两次都执行的停止政策已经给出。这里的两次全量生成也不同于仅因技术错误而重试；若改用条件重试，才需另定触发与停止条件、最多次数及失败处理。

**修复或下一步：** 若想比较带重试系统，先规定实际可用的触发条件、选择器、总时间、调用和费用预算，再冻结并评价最终返回的一个决定。可比较相同预算下的候选系统，或明确报告不同预算的取舍；保留本次 7/8 为有用的候选覆盖诊断。

**理由：** 工具带来外部信息，也改变了运行资源和失败路径。系统表现提高可以有实际价值，但“哪套允许使用的系统更合适”与“基础模型是否改善”是两个问题。

**缺失证据：** 真实部署还需工具可用性、访问权限、信息版本、最终端到端时间、调用费用及合适的目标样本。此处没有真实价格，也没有足够证据计算部署收益。若要归因，还缺对应的匹配组件比较。

**修复或下一步：** 把行名写成 B1 加工具及 K1，保留各项资源预算与执行状态。依据事先允许的条件比较整个系统，或另做能隔离目标因素的比较；不要把整次观察一概判为“无效”。

## 4. 新证据会改变哪一条结论？

下面两题各自从基线出发；T1 不适用于 T2。先写你愿意保留和撤回的句子，再读解析。

### T1：清单相同，实际输入却少了一项

**新增事实：** 审计拿到 A 的另一份导出档案。清单仍写 `resize-v1`、D1 和 p1–p8，与 B 一致；实际预处理轨迹却显示 p7 因解码拒绝被丢弃，生成输入只有 p1–p6、p8。这七项输出与原表相同，p7 没有生成输出。旧导出把 p7 填成“错误”，来自默认失败标记，不能把原表里的 `GO` 当作这个分支真实生成过的答案。B 的八条原记录完整。原政策已规定缺失必需输出也计失败。

**先问：**

1. 是否仍能声称两个模型实际收到了相同的八项输入？
2. 哪个数可以保留，哪种解释必须更正，接下来应补什么？

**解析：** 不能保留“同样八项都进入生成”的说法。A 的 p7 应记录为预处理失败、无生成，撤回虚构响应并保留修订链。在全部八项必需任务的端到端口径下，A 仍为 6/8，B 仍为 5/8；A 的失败原因变了，分数恰好没变。这个保留量描述的是实际执行的流程，包括预处理故障，不能再解释为在相同八项模型输入下的比较。

**修复与未知：** 核对原始输入标识、预处理输入输出、丢弃原因和生成请求，修复后按声明政策重新运行受影响的比较并留新运行 ID；只有确认另一侧条件和保留记录仍适用，才可以说明为什么复用它。仅给 p7 补一条猜测结果不能修复。p7 真正送进 A 时会答什么仍未知，其余七项的原观察并未因此全部消失。

这题说明“清单一致”和“执行一致”是两层证据。早期 MLPerf 对提交结果的审计讨论，也把检查实际执行视为必要工作，不能由配置表替代。[MLPerf Inference v2，§VII.E](https://arxiv.org/pdf/1911.02549v2)

### T2：同一批输出，用修正后的判分器重新计分

**新增事实：** 这次使用完整的基线输出，与 T1 无关。发现运行前已有的格式说明 F1 允许首尾 ASCII 空格，S1 却严格匹配原串，这是已记录的解析缺陷 PB1。S2 只移除首尾 ASCII 空格，再按原词表和 L1 判定；它不改标签、输出、时限、题目或生成过程。修复依据是已有 F1，已用适用于双方的格式例子核对，不是为了偏袒一方而挑规则。现在双方所有保留输出都用 S2 重计。

**先问：**

1. 哪些逐题结果和汇总变了？这是否新增了模型生成？
2. 应保留哪些历史？如果规则是看分后为偏袒一方而改，还需说清什么？

**解析：** 唯一改变的是 B 的 p6：`␠HOLD␠` 去掉首尾空格后为 `HOLD`，由错误变正确。A 仍为 6/8；B 从 S1 的 5/8 变为 S2 的 6/8。B 的 p7、p8 仍超时，没有因解析修正凭空得到答案。这是**同一输出的重新计分**，不是一次新的模型生成运行，也不能证明重新请求模型还会返回完全相同的内容。

| 结果版本 | A 全任务成功 | B 全任务成功 |
| --- | --- | --- |
| S1 原结果 | 6/8 | 5/8 |
| S2 重计结果 | 6/8 | 6/8 |

**修复与未知：** 保留 `run-A1`、`run-B1` 及未改变的输出文件身份、L1、S1 旧结果、S2 新结果、PB1 修复说明和重计时间。档案中的虚构时间为：  
2026-09-20 10:00 UTC 生成，10:10 用 S1 计分，次日 09:00 用 S2 重计。若实际发生的是看分后为偏袒 A 或 B 而改规则，则除了软件版本变化，还须披露评价规则的适应性选择，并用有依据的规则和适当独立证据另作确认；不能只用“修复”一词遮盖它。

## 5. 把原则迁移到语言模型与真实报告

换成语言模型任务，同一题库和“准确率”名称仍不足够。如果从单次无检索回答换成两次生成加网页检索，还需交代模型精确版本、提示与解码设置、检索内容或快照、工具可读信息、尝试和停止预算、最终答案选择方式、判分器，以及是否看过测试反馈来修改这些设置。网页内容与服务版本未知时，就把它们列为缺失证据，不假装固定种子已经控制了全部变化。

报告可以沿着以下顺序写，遇到缺口就停在有证据的地方：

1. 写明问题和完整受测对象，以及这次允许变化的因素
2. 固定任务、参考、配置、资源和计分政策，说明开发选择与测试查看的时间关系
3. 核对每个必需任务实际经过哪些组件，保留失败、弃答和超时
4. 按声明口径汇总，同时报告能解释结果的完成情况与条件差异
5. 给出有限观察、不能推出的结论、所需新证据和最小修复；区分重计与新运行

一个报告可以在“有限任务上的描述”上充分，在“部署总体结论”上仍然不足。P1 保留 6/8 与 5/8；P2 改正口径；P3 保留候选覆盖诊断；P4 披露开发选择；P5 改写系统边界；T1 修正执行证据；T2 保存版本化重计。判断的目标是说清各自还支持什么，而不是遇到一个变化就宣布所有比较都毫无意义。

也不能反过来，把记录齐全当作结论已经成立。Pineau 等对复现性计划的讨论明确保留了效果证据的限制；本文据此坚持把记录充分、计算正确和科学结论充分分开检查。[Pineau 等，JMLR 2021，§5–6](https://jmlr.org/papers/volume22/20-303/20-303.pdf)
