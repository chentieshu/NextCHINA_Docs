# Markdown 表格：内容驱动的响应式布局

## 本轮替代的设计

本文件替代早期表格审计中“按字符估算 em 列宽、JS 分配比例、固定表格布局、逐表 preferred 宽度”的布局约定。历史审计文件保留为当时的结果，不作为当前设计规范。知识内容、模型成绩、报价及来源日期不改动。

解析继续使用 react-markdown + remark-gfm，数学与 Mermaid 仍走现有组件。无需引入第二个 Markdown 解析器、DataGrid 或编辑器；本次改变的是布局和回归检查，不是 Markdown 方言。

## 单一宽度归属

工作区的 `.ws-reading-column` 决定可用宽度。普通知识文章最大 820px，reference 数据页最大 1120px；两者都不超过扣除工具条、侧栏、关联栏、内边距与滚动槽后的真实空间。标题、提示和表格共用同一阅读列左右边界，不再出现 1280px 父容器、820px 文段、单独估算的表格宽度三种规则。

`MarkdownTable` 不再写入 table 宽度或 colgroup 比例；table-layout:auto 由浏览器使用真实字体、内容与内边距计算列宽。表格边框宽度为阅读列的 100%，超宽的内部表格只在 `.md-table-scroll` 中滚动。

## 单元格与内容

- 数值和 ISO 日期列只提供类型提示，保持完整显示，不将一个值切成多行。缺失标记不当成实际数值。GFM 作者的左/中/右对齐不被类型判断改写。
- 短表头保持完整，长表头可换行；长说明、URL 和行内代码允许换行。常规文字有基础可读宽度，长说明在多列表格中有更宽的下限。
- 列数不再决定是否强行挤进手机：普通两列表通常能适配，但不可压缩的内容仍允许横向滚动。不会隐藏列、截断数据、缩小整张表，或在手机上丢掉表格语义。
- 单元格类型通过 React 子节点或其 HAST 节点标记，同样覆盖自定义 th 和手写模型索引的行表头。保留 caption、thead、tbody、scope 和表头关联。
- 不声称支持 Markdown 方言之外的任意原始 HTML 合并单元格或电子表格功能。

## 滚动与主题

ResizeObserver 仅测量是否溢出和按钮边界，不再反馈修改列宽；字体加载、图片加载、窗口和面板变化均重新检查滚动状态。仅在真实溢出时出现提示、左右按钮和滚动区域键盘焦点。按钮通过 aria-controls 指向独立滚动区域，兼容从右到左的滚动方向和减少动态效果设置。

表头、条纹、边框、悬停、焦点和滚动条继续使用局部明暗主题变量；无盒阴影、无文字阴影。数字采用等宽数字特性。表格字号在 16px 根字号时约为 14–15px，根据实际内容容器而非整屏宽度变化。

## 验证

保留现有全部文档渲染清点、侧栏/关联栏变化、明暗主题、图片失败/成功、GFM 对齐、公式、Mermaid 与强制颜色模式测试。删除依赖旧列宽估算器的数学测试，替换为类型判定及真实浏览器几何断言。

新增 `workspace-tables-responsive.spec.ts` 检查 320–2560px 的实际榜单/价格表、标题/表格两侧一致、无注入列宽，以及数值单行且不溢出自身单元格。专用 fixture 覆盖 30 位数值、长表头、长代码、缺失值、16/20/24px 根字号与 RTL。旧大屏检查仍覆盖 3840px；生产测试使用构建后的页面。测试用样例不是现实报价。

本机可执行构建与静态渲染，但本次浏览器验收使用 GitHub Actions 的 Chromium。未声称真实 iOS Safari、Firefox 或所有字体均已设备实测。最终执行结果以相应提交的工作流记录为准。
