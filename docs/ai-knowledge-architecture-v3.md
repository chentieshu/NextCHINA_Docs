# NextCHINA AI 知识架构 V3：一张网，从 0 到 1

## 产品定义

NextCHINA 不再把“文章、专题、榜单、教程、关系图”当成互相独立的内容产品。唯一核心资产是 **AI Knowledge Ontology**。

- **知识节点**是可复用组件：Softmax、Embedding、Transformer、RAG、KV Cache 等只定义一次。
- **专题**是组件组合：LLM、VLM、Agent、视频生成等引用公共节点，并补充自己的专属节点。
- **文档**是节点或节点集合的解释资源，不拥有自己的图谱。
- **目录**是从 0 到 1 的学习入口，允许树形浏览，但不宣称知识本身是一棵树。
- **关系图**全站只有一张。搜索、聚焦、过滤只是改变观察窗口，不生成页面专属图。

## 从 0 到 1 的六个阶段

### 00 · 建立全景
AI 的定义、任务、历史、能力边界、人机关系。目标是先知道整张地图有哪些区域。

### 01 · 数学、数据与学习
线性代数、概率统计、微积分、信息论、优化、数据生命周期、训练、泛化、强化学习。它们是后续模型机制的公共依赖。

### 02 · 模型、算法与模态
经典机器学习、搜索与规划、概率模型、神经网络、Transformer、语言、视觉、图像、视频、音频、3D、多模态。这里解释“计算结构怎样把输入变成输出”。

### 03 · 系统、Agent 与工程
检索、RAG、Agent、工具调用、记忆、工作流、世界模型、具身智能、训练基础设施、推理服务、端侧与成本。这里解释“模型怎样成为可靠系统”。

### 04 · 评测、产品与实践
评测方法、榜单、价格、产品、API、教程、实验与交付。这里回答“怎样选择、怎样使用、怎样验证”。

### 05 · 应用、治理与前沿
行业应用、安全、隐私、版权、治理、社会影响、论文、产业与未来。这里回答“AI 在现实世界中产生什么效果、风险与新问题”。

## 复用规则

同一个概念只有一个 canonical ID。专题通过引用组合知识：

```
Softmax
├─ Attention 权重
├─ LLM 输出概率
├─ 分类模型
└─ 温度与采样

Embedding
├─ LLM Token 表示
├─ VLM 跨模态表示
├─ 向量检索
├─ RAG
└─ 推荐系统

Transformer
├─ LLM
├─ VLM
├─ DiT
└─ 视频模型
```

因此“LLM → Softmax”和“数学 → Softmax”不是两篇互相复制的知识，而是两个入口指向同一节点。

## 三种关系

1. **目录归属 browse_child**：为了阅读定位形成的树形入口，不代表严格学术包含。
2. **建议先学 recommended_before**：从 0 到 1 的推荐依赖，是教学顺序而非逻辑必要条件。
3. **知识关联 related**：组件复用、机制连接、工程影响或跨领域关联；必须附带 reason，避免只因为名称相近就连线。

未来若需要更严格的科学语义，可在数据层扩展“uses / evaluated_by / implemented_by / derived_from”等关系，但第一阶段继续保持三类可解释关系，避免伪精确。

## 唯一关系视图

关系视图固定为 **一张宏观关系图**，用来看清整个项目，而不是按领域、路径、文档拆成多张图：

- 图上同时有 14 个领域、已启用专题，以及每一条已经写明的知识关联（建议先学、知识关联、阅读路径上的概念）。
- 没有关联、也没有文档的空大纲留在目录里，不铺进这张图。
- 右侧索引按原文列出全部关联，包括专题对共享概念的引用。
- 搜索可以定位任何微观概念。聚焦时仍是这一张图，只是把该知识点的邻域留在画面里。
- 文档不是图谱节点；点专题或概念上的阅读入口进入文档。
- 当前阅读页面不生成另一张局部关系图。

## 文档大纲与图谱的关系

侧边栏继续采用树形结构，因为树适合“找内容”；关系图采用网络结构，因为网适合“理解连接”。

```
侧边栏（学习入口）        全局知识网络（真实连接）
00 全景                  数学 ─┐
01 基础                  数据 ─┼─ Transformer ─ LLM ─ RAG ─ Agent
02 模型                  概率 ─┘        │        │
03 系统                              VLM      评测/价格
04 实践                               │
05 世界                              视频/图像/3D
```

两者共享相同 canonical node IDs，不维护两套知识。

## 内容完成标准

一个微观知识点最终应能回答：它是什么、为什么存在、输入输出是什么、内部怎样计算、依赖什么、被哪些系统复用、如何验证、哪里会失败、有哪些证据和进一步阅读。

框架节点可以先存在而没有文章；没有正文时必须显示“待完善”，不能把目录存在等同于内容完成。


## 主学习骨架：12 个连续阶段

六个宏观阶段用于首页和宏观定位；实际从 0 到 1 的学习大纲进一步展开为 12 个连续阶段。规范数据见 `content/garden/master-outline.json`：

1. **00 · 建立 AI 全景**：定义、任务、历史、边界；
2. **01 · 数学与计算语言**：线性代数、概率、微积分、信息论、优化；
3. **02 · 数据怎样变成能力**：数据、训练、泛化、后训练、强化学习；
4. **03 · AI 与机器学习算法**：经典 ML、符号、搜索规划、概率模型、神经网络；
5. **04 · 深度学习与基础模型**：Transformer、Attention、语言模型与统一多模态；
6. **05 · 语言、视觉、音频、视频与 3D**：各模态的表示、理解、生成与融合；
7. **06 · 检索、RAG、Agent 与系统**：从单模型到工具、记忆、规划和可靠执行；
8. **07 · 世界模型与具身智能**：状态、动作、控制、机器人、仿真与现实反馈；
9. **08 · 算力、训练与部署工程**：硬件、分布式训练、推理、压缩、服务与成本；
10. **09 · 评测、榜单、价格与选择**：能力、效率、可信性、成本和真实任务效果；
11. **10 · 产品、工具、教程与实验**：API、产品、创作、开发、实验和交付；
12. **11 · 行业、安全、治理与研究前沿**：现实应用、风险、社会影响、证据和未来。

这 12 个阶段仍然不是 12 套独立知识。它们是 canonical graph 的教学投影。
